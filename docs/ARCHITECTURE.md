# Comprehension core

`internal/core` owns repository scanning, parser registration, normalized graph facts, local evidence, ranking, Tours, local change comparison and optional explanation preparation. It has no HTTP dependency. The root HTTP handlers and `tour`/`review` commands adapt the same services to browser and terminal surfaces. `internal/model` is the explicit network adapter.

A Repository holds an index and matching graph snapshot. Refresh scans and builds a replacement before atomically publishing it. Ordinary navigation queries do not rescan. Parsers claim a file from its path and a bounded content peek, in explicit priority order; YAML files share one structural classification so Ansible and Kubernetes content cannot both claim a file. Current-source reads use the registered parser; graph orientation verifies source identity. Exclusion and module-identity changes make stale snapshots unavailable until refresh. Typed core errors retain their category through HTTP adapters.

Each graph node and edge carries source provenance. Go AST/type information resolves only indexed local packages; no compiler/build commands or module fetching are invoked. Missing targets and dynamic interface dispatch are omitted. HCL literal local module sources link indexed units. Ranking explains its heuristic factors separately from facts. Evidence providers may fail independently; missing Git does not disable source navigation.

The browser binds semantic navigation actions to keys, maintains bounded in-memory reading history, and uses sequence checks for late responses. Local worker tokenization produces token data only; DOM text-node rendering preserves the source. Pure review helpers (picker matching, diff rows, unread search) live in `ui/review.js` without DOM access so they are tested directly; diff rows use tokens only when they reproduce the line exactly.

A review compares two sides, each a local commit, the staged index or the indexed working tree. The working tree side is the live index and graph; any other side is rebuilt as a snapshot from Git objects listed with `ls-tree` or `ls-files --stage`, filtered by the same exclusions, size limits and vault checks as a scan. Objects identical to indexed working-tree source are not read again, and the rest are read in one `cat-file --batch` pass shared by both sides, bounded to 32 MiB. Each snapshot gets its own graph, so relationship changes and caller/test signals are differences between two graphs rather than text heuristics. Line hunks are computed in process with patience anchors and an exact table between them, capped so cost stays bounded. Rename pairing compares removed with added units of the same kind and accepts only mutual, unique best matches. Listing reviewable changes uses bounded read-only `log`, `for-each-ref`, `merge-base` and name-only `diff`; commit subjects and branch names are treated as untrusted display text. A review whose head is not the working tree does not require a fresh snapshot, and surfaces label its relationships as belonging to the reviewed snapshot.

Explanation preparation is local and bounded. The surface displays the exact prompt and model destination, then confirms that the approved digest matches a newly prepared payload. Budget reservations are synchronized, failed requests roll back, and explanation cache writes replace private temporary files atomically. AI text is never promoted into the source graph.
